# Step 2A - Experimental methodology and limitations
Runner: `python/step2a_campaign.py` (imports v1 functions from `fault_campaign.py` unchanged). Profiles are explicit (`PROFILES` dict, configs dumped in `campaign_summary.json`). Mission trace seed 2024 (600 ticks x 20,000 cycles), injection seed 4242 (original), fault database `results/fault_db.csv` (2,515 faults, unchanged), detection tables and netlists unchanged, Eq.(2) weights (1,1,1,1,1) unchanged.

## Profiles
`v1_adaptive` (all Step-1/2A OFF); `fixed_N5/10/20/40/80` (N=20 is the principal baseline, fixed before results were seen); `s1_recovery_only`; `s1_all3` (corrected adaptive reference); `s2a_all3_evid` (arisk_deg=0); `s2a_all3_evid_aflag` (arisk_deg=1; reproduces s1_all3 results exactly on the mission).

## Experiment 1 - first detection, fault-free schedule replay
Per fault, the first detecting test that starts after the injection cycle in the profile's fault-free schedule. This is exact for ONE fault per episode in this model: before a detection every test passes and raises no manager event, so manager inputs equal the fault-free run (Experiment 2 re-derives every first detection in closed loop and asserts equality for all faults/profiles). It does not evaluate the scheduler's response after a detection.
Metrics: coverage (total / block / tier), latency mean/median/p95 over detected faults, censored mean latency (undetected counted as end-of-mission minus injection), total test cycles, mission-interruption cycles (non-ONLINE test cycles on mission-active ticks; ONLINE tests are non-interrupting), counts of full/partial/MBIST/online tests, state occupancy, per-block full scans, ticks since last full scan, max gap, overdue blocks (derived from decisions, independent of `lastfull`), starvation classification. The fixed baseline schedules full+MBIST of all blocks every N ticks regardless of state (its schedule is independent of all adaptive signals; test E14).

## Experiment 2 - closed-loop diagnostic response
Sequential single-persistent-fault episodes (manager reset per episode; same injection cycle; fault persists to end of mission; no simultaneous multi-fault episodes). A decision fails for the faulty block if any executed component on it detects the fault per the unchanged tables; the result returns as `res_fail` on the next tick. Reported: flagged episodes, flags cleared while the fault persists, DEGRADED ticks, interruption, episodes ending DEGRADED, overdue blocks at end. Fixed profiles ignore feedback, so their DEGRADED/flag figures are aging-flag artefacts, not response data.
Note: in s1 profiles a cleared flag may be an aging-flag clear, not a fault clear; only `s2a_all3_evid` (arisk_deg=0) isolates clearing of a diagnostic fault while the fault persists (117/2451 episodes; the partial-scan diagnostic cannot detect every fault in the unchanged detection tables).

## Limitations
Behavioural aging (cumulative stress x rate) and fault models, not physical NBTI/HCI; a diagnostic passes iff no detecting test runs; DIAG has no independent detection table (decision result = detecting components of the same decision); one scheduler tick = 20,000 cycles and every test fits one tick; one mission trace and one injection seed (single-seed, no confidence interval - multi-seed is Step 3); thresholds (deg_th, recov_n, margin, overdue_ticks, fair_gap) are assumptions; Yosys was not run, so no area/timing/power for the added registers; 16-bit age horizon (above). No silicon or physical-aging claim is made.
